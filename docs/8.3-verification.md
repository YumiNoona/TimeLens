# TimeLens 8.3 implementation and verification

Only roadmap features 4 and 5 were added: idle/offline reconciliation and collection-time privacy rules.

## Fixes and resource reductions

- Native foreground, idle and browser checkpoints are throttled to ten seconds; switches, browser leave and shutdown still flush immediately. Cheap idle detection retains its one-second cadence.
- Input hooks cache foreground process identity for half a second, validating the window/process identity on each input. Foreground callbacks no longer resolve the same process twice.
- Writer queue dequeue/drain now shares the synchronous-write lock, preventing queued operations from overtaking deletion or synchronous state changes.
- All native timers are awaited during shutdown. Removed background aggregation for the discontinued goal UI; legacy data is preserved.
- Firefox persistent background changed to an event page, with initialization-safe event handlers. Both companions use event-driven tracking plus a 30-second alarm instead of five-second polling. Companions older than 8.3 are marked outdated and fail closed with privacy filters configured.
- Content media collection no longer installs whole-document MutationObservers. Disabled/private/excluded collectors are dormant; queued input respects privacy edits, pauses and deletion boundaries.
- Dashboard reuses the summary response rather than separately fetching the same site/audio/media aggregates. Browser live overview follows refreshed props. Browser date changes use a consolidated summary. Non-activity views do not poll the main summary.
- Summary, apps, categories, timeline and website attribution share the daily foreground ledger. Historical heatmap data is cached separately for ten minutes and invalidated after rule changes, retention changes and deletion.
- SQLite expression indexes support interval end-time predicates without dropping compatibility with legacy offset timestamps. Regression checks verify the daily query uses its index.
- Reordered rules update the live classifier, not only SQLite. Backfill uses the same classifier for supported rule types/targets. Glob matching now has the regex timeout too.
- Paper theme survives restart; custom export dates use the local calendar.
- Removed the full Tabler webfont and its vulnerable build dependency chain. Build-time SVG selection emits 257 referenced icons; removed icon names have explicit compatible fallbacks.
- Dependency advisories corrected in both dashboard and website lockfiles. SDK/test commands work with the installed SDK and the actual xUnit runners.
- Desktop, installer source and browser packages are versioned 8.3.0. Firefox submission is no longer gated on desktop/extension version equality and skips an already-published companion version.

- .NET startup regressions pass; tracking suite: 13 tests pass, including repeated lifecycle/handle soak, privacy, offline reconciliation, overlap rejection, deletion/retention, leave flush and index selection.
- Dashboard and website production builds succeed; both npm audits report zero vulnerabilities.
- Native AOT publish succeeds. Packaged EXE smoke checks pass for embedded assets/runtime, fresh DB, tray/toast, block contracts, offline write/read/delete/export, privacy/pause settings and summary APIs.

- `git diff --check` passes.

## Measured footprint

The dashboard build is approximately 983 KB, including text fonts and public assets; the approximately 4.1 MB icon-font payload is gone. The self-contained Windows executable is approximately 20.3 MiB.

After a 15-second warmup, a 30.32-second isolated background sample with default collection settings measured 0.103% of one CPU core, 35.71 MiB peak working set, 18.13 MiB peak private memory and a handle delta of +2. This is a short, mostly idle local measurement, not a worst-case limit. Large history queries, busy input, playback and native notifications can use more resources. The existing 21-cycle lifecycle soak also passes its handle-growth check.

Reproduce with:

```powershell
npm test
npm run test:dotnet
npm run build --prefix src/TimeLens.Dashboard
npm run build --prefix web
.\scripts\publish.ps1 -SkipInstaller
.\scripts\test-startup.ps1
.\scripts\test-block-modes.ps1
.\scripts\test-resource-budget.ps1 -SampleSeconds 30
```

## Remaining release/validation work

The EXE and both extension ZIPs are built locally. No commit, push, release, signing or store submission was performed. Inno Setup is not installed here, so a new Windows installer was not built; its source version is updated. Firefox behavior was checked by mocked browser-API regressions and package lint, not a long-running live Firefox resource benchmark. A populated-history benchmark and visual/manual cross-browser acceptance pass remain advisable before shipping. Privacy rules affect new observations, not old history.

The event-page and alarm approach was checked against Mozilla's primary documentation: [background scripts](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Background_scripts) and [alarm creation](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/alarms/create).
