# TimeLens 8.4.0 verification

Local verification date: 2026-10-28. Android is a preview; this document does not assert complete desktop parity or physical-device certification.

## Completed checks

- Node regression suite: 10 passing tests, including extension behavior, release selection, timeline boundaries and version alignment across desktop, dashboard, website, installer and Android.
- .NET startup and tracking regressions: 15 passing tests. The secure API regression now verifies session renewal on an authenticated request while anonymous settings access remains rejected.
- Svelte component checks: zero errors and warnings. Both frontend production builds pass. The dashboard now uses TypeScript 6, within svelte-check's supported peer range, so component checks run as part of every build.
- npm audits: website has no advisories; dashboard has no high/critical advisories. Two low-severity advisories remain through the Svelte build plugin's `deepmerge` dependency, for which npm reports no upstream fix. It processes trusted build configuration and is not shipped as a runtime dashboard API.
- .NET dependency advisory check reports no vulnerable packages.
- Windows packaged startup smoke check passes using a self-contained, trimmed **managed** executable: fresh database, embedded dashboard/runtime, tray, toasts, settings, browser block contract, custom block media and summary APIs.
- Native Windows block probe passes Hide, Kill, Strict and relaunch enforcement using that same local executable.
- Browser smoke check in headless Chrome: mobile More → History, Apps, Timeline, More → Settings; desktop resize; zero page errors and no document overflow at 390 px.
- Android Gradle build, eight JVM ledger tests and Android lint pass (zero lint errors; dependency-update/style warnings remain). A dedicated API 35 emulator passes the database/privacy instrumented test, including idempotent import, clipping, exclusion/deletion and restored-app boundaries.
- Android launches with permission onboarding; granting Usage access imports real emulator foreground events. Phone and tablet screens were visually reviewed. The privacy manifest has no Internet permission and explicitly excludes data from system cloud backup/device transfer.

## Packaging and release boundaries

This machine lacks the C++ linker needed for Native AOT; the local Native AOT publish attempt reports that missing prerequisite. The tag-triggered GitHub release workflow builds the final Windows Native AOT binary on `windows-latest`, builds its installer, includes the checked Android APK and extensions, and creates SHA-256 checksums. Local managed smoke checks do not establish that the final CI-produced Native AOT artifact passed the same tests; verify the downloadable release artifact as a separate step.

The Android asset is debug signed and carries the preview label in the app, filename and release notes. No production signing key or store-ready Android claim is included. Optional local PC pairing, strict blocking, URL/media capture, scheduled archival and background timer alarms remain roadmap work. Windows Firefox publishing now requires the explicit `PUBLISH_FIREFOX_ON_RELEASE=true` repository variable in addition to AMO credentials; GitHub release publication does not implicitly request a store submission.

The previously tracked root `TimeLens.exe` is removed from source control; generated binaries belong in release assets. Build scripts still place local output at the root when requested.

## Reproduce

```powershell
npm test
npm run test:dotnet
npm run build --prefix src/TimeLens.Dashboard
npm run web:build
npm audit --prefix src/TimeLens.Dashboard --audit-level=high
npm audit --prefix web --audit-level=high
dotnet list src/TimeLens.sln package --vulnerable --include-transitive
./scripts/publish.ps1
./scripts/test-startup.ps1
./scripts/test-block-modes.ps1
```

For Android, follow [android/README.md](../android/README.md). Instrumented tests modify only the dedicated test installation's data; use an emulator or separate profile.
