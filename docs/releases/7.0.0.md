# TimeLens 7.0.0

TimeLens 7 improves foreground tracking and makes History explain where your time and input went. The desktop app, Chrome extension and Firefox extension are all version 7.0.0.

## Tracking fixes

- Immediate foreground hooks and a one-second fallback retain short app switches. Fresh process resolution improves executable identity, including Windows packaged apps.
- Durable checkpoints retain multi-hour sessions. Observation gaps, sleep, lock and stale browser reports stop extending activity instead of inventing time.
- App input counts belong to the executable receiving input and flush every five seconds and on normal shutdown.
- Browser heartbeats and page-title refreshes extend a session instead of inflating visit counts. Website time requires matching foreground browser activity, excludes idle intervals and is allocated across local midnight.
- Historical overlapping browser rows are clipped during reporting. Missing observations cannot be recovered, and corrected historical totals may be lower when older rows included background or overlapping time.

## Detailed History and quality of life

- Searchable website and executable tables with time, clicks, keystrokes, sessions and last-seen details; sort and export the selected table to CSV.
- Expand websites for page URL/title, browser, duration and input; expand apps for recorded window segments.
- Top Sites now labels active duration and session counts. The hourly website chart shows time rather than unlabeled event counts.
- Seconds and short switches remain visible; Apps includes every recorded app, and timeline grouping does not fill unrecorded gaps.
- Older website input appears as unavailable (—), never a fabricated zero. Website input is a breakdown, not an addition to desktop input totals.

## Chrome and Firefox extensions

Both packages include the same Notify reminders and Strict blocking behavior, focused-tab tracking, privacy exclusions, aggregate website click/keystroke counting and connection popup. Chrome uses Manifest V3 with worker/alarm recovery (Chrome 120+); Firefox 140+ uses its persistent background extension and built-in browsing/website-activity consent.

Input collection counts trusted events on focused pages. It does not read typed characters, key values, passwords or form contents. Retries retain the original batch ID so a retry cannot double counts. Pending input stays in memory for at most two minutes; closing pages or prolonged outages can lose undelivered counts. Browser and input collection follow desktop settings.

## Downloads and upgrade

- **TimeLens-Setup.exe**: Windows installer.
- **TimeLens.exe**: standalone Windows executable.
- **TimeLens-Chrome-Extension.zip** and **TimeLens-Firefox-Extension.zip**: extension source packages for testing and store submission.
- **SHA256SUMS.txt**: checksums for all four packages.

Existing valid local history is retained. Install the desktop update and update your companion extension. Chrome Web Store submission and Mozilla signing/review are separate from this GitHub release; these ZIPs do not update the published store listings. See `docs/chrome-web-store.md` for submission instructions and privacy disclosures.

## Validation and accuracy boundaries

Automated checks cover long sessions, restart/migration, short switches, input attribution and retry deduplication, overlapping legacy tabs/idle spans, local-midnight totals, actual HTTP routes, extension focus/private-page handling, Notify/Strict parity and timeline gap preservation. Dashboard build and native Windows packaging are release checks.

Tracking is observational, not a guarantee of perfect attendance measurement. Reading remains active during the configured idle grace; selected foreground media can sustain activity for up to two hours. Extension observation loss has a 65-second lease. Missed OS callbacks, inaccessible/elevated windows, browser restrictions and failed storage can affect capture. Browser visual preview was unavailable in this development environment; interactive stopwatch and clean-machine acceptance remain manual checks described in `docs/tracking.md`.

Design references include ActivityWatch foreground/AFK watchers and count-only input tracking, implemented independently. Activity remains on your computer.
