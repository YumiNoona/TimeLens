01

GET STARTED

One idea. Two native apps.

TimeLens helps you see where your attention goes and limit distractions. The Windows app runs in the tray with a local browser dashboard. Android has its own native Today, Apps, History, Block and Settings screens.

Understand your day

App totals, visits, categories, goals and saved history.

Make room for focus

App and website blocking with controls suited to each platform.

Stay in control

Local storage, optional permissions, exclusions, retention and exports.

Separate device histories

Windows and Android work independently. They do not currently pair or sync.

02

WINDOWS

Install and start tracking

  1. 1
    Download Setup

    Install TimeLens for Windows, or use the portable EXE from the release. Both include the embedded dashboard and runtime.

  2. 2
    Choose startup behavior

    The installer offers optional launch-at-sign-in and a desktop shortcut.

  3. 3
    Open the dashboard

    Use the tray icon, or visit http://127.0.0.1:47821/ while the app runs.

  4. 4
    Connect your browsers

    Add the companion to each browser profile where you want website-level activity and blocks.

Windows 10/11, x64. No separate .NET installation is required.

03

ANDROID

Made for your phone

Download the signed Android APK for Android 10 or later. The AAB in the release is for Play Console upload, rather than direct installation.

  1. 1
    Allow Usage access

    This reads foreground app usage and measures app allowances. TimeLens does not request Internet access.

  2. 2
    Explore your activity

    Check Today, search and filter Apps, or open History for range totals and per-app visits. Each app has one total with an expandable visit list.

  3. 3
    Set up optional blocking

    Open Block, read the disclosure and enable the Android Accessibility service. A downloaded APK may require Allow restricted settings in Android App info first.

  4. 4
    Make it yours

    Use the top sun/moon for light or dark mode. Settings controls dashboard modules, icon colors, compact cards, clocks, retention and privacy.

Native switches, clear search/filter controls and keyboard actions keep everyday changes quick. Optional website tracking reads known browser address bars; hidden bars, private-tab behavior and unsupported browser versions can leave gaps.

04

BROWSERS

Connect the browser you use

Companion 9.0.0 adds website visits, aggregate input counts, observed media and website blocking to the Windows app. Chrome, Edge and Brave use the same Chromium implementation; Firefox has a separate package.

CONNECT

Pair each profile once

  1. Keep the Windows app running.
  2. Open Settings → Privacy center and generate a pairing code.
  3. Enter it in the extension popup and choose Pair.
  4. Wait for Connected. Pairing survives normal restarts and upgrades.

PACKAGES

Ready for store submission

The release includes Chrome, Edge, Brave and Firefox ZIPs. Store publication is separate. Chromium ZIPs can be extracted and loaded unpacked for local use; Firefox release installations require a Mozilla-signed add-on.

Firefox store listing → — its published version may differ until updated.

Privacy before collection.

Private/incognito tabs are excluded. URL detail and title storage follow your Windows settings before observations are sent. No typed characters or form contents are recorded.

05

ACCOUNTING

Time with context

App time
Windows counts one foreground app at a time and separates idle, lock and sleep. Android uses local Usage events and its saved archive.
Website time
Website time is part of browser app time, not extra time to add to the total. Windows needs a paired companion; Android needs optional address-bar access.
Media
Windows records supported media separately from foreground time. Playback observations are conservative; buffering, seeking and missing observations are not treated as watched time.
Input
Windows input statistics are aggregate keystroke and click counts. Typed text, key values and passwords are never captured. Android does not collect global input counts.
06

YOUR ACTIVITY

From totals to individual visits

Today gives a daily summary. Apps shows usage by app and category. History reveals trends and selected-day detail; search, filtering and expandable visits help find what matters.

Windows dashboard

Today, historical reports, app/category breakdowns, browser reports, chronological timelines, separate media and aggregate input statistics.

Native Android

Daily goals, favorites, app filters, 7/30/90-day and year summaries, sorted per-app history and expandable visits. The long activity-calendar grid is removed.

Retention limits the history available. An update cannot recover events the operating system already discarded or that were never observed.

07

BOUNDARIES

Choose useful limits

WINDOWS

Focus and blocking

Use Focus Mode, app/site rules, reminders or strict blocking, timed targets, custom banners and optional password protection. The companion is needed for website enforcement.

ANDROID

Comfort or Strict

Comfort allows a chosen number of minutes in a rolling 24 hours. Strict blocks access while enabled. Add individual rules or create app rules together, customize the blocking banner, and protect edits with an optional PIN.

Goals are comparisons; they are not automatically blocking rules. Android blocking depends on the Accessibility service. Personal-phone removal protection adds a confirmation step; Android-enforced uninstall policy requires an independently provisioned, authorized managed-device role.

08

CONTROL

Keep what is useful

Change categories and goals, choose retained history, exclude sensitive activity and control optional collection. Windows includes title/URL privacy choices, aggregate-input and media controls, recording pauses and optional offline-work review. Android groups appearance, dashboard modules, permissions, storage, privacy and protection into expandable settings.

Android uses a single sun/moon theme control, with readable native switches and keyboard actions. Protection changes remain subject to the PIN when configured.

09

YOUR DATA

Local by design

Windows keeps its SQLite database under %LOCALAPPDATA%\TimeLens. Android keeps its archive in app-private storage. Neither requires an account or uploads activity to a cloud service.

Windows exports CSV and JSON. Android exports app activity as CSV/JSON and restores supported JSON activity exports. These activity exports are not a complete backup of every rule, website observation, category, preference or PIN. Review what an export includes before replacing a device.

10

HELP

Get back on track

The extension says Desktop offline

Start the tray app and check the exact browser profile is paired. A saved token does not mean the local app is currently reachable. Generate a new code only if pairing is missing or rejected.

Android blocking stopped

Check Usage access and the Accessibility service, then review Android battery restrictions. Browser bars and browser updates can affect website observation. Safe system apps remain accessible.

Some time is missing

Check collection settings, exclusions, permissions, retention and the selected day. Private tabs, unsupported browser pages, sleep and collection gaps are not reconstructed as activity.

The keyboard covers a control

Use Search or Done to finish typing. The native app adjusts its page for the keyboard, and returning to a saved search keeps the query without reopening typing.

11

MAINTENANCE

Update without losing your place

Windows and Android now display version 1.0.0; browser companions use 9.0.0. Existing higher-numbered Windows versions need a manual installation of this reset release. Future updates can follow the new version line.

The signed Android APK keeps an increasing internal build number and the current release signing identity, so it updates the signed Android releases in place. Old previews signed with a different key cannot be updated by this key.

Uninstall through your operating system. Keep a backup or export first if you want to retain activity. On Android, turn off the optional administrator removal step before uninstalling; authorized managed-device policies need their normal administrator recovery path.
