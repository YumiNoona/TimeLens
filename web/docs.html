GET STARTED

What TimeLens does

TimeLens records one exclusive foreground application timeline, separates idle and away spans, and records media playback as a clearly separate concurrent signal. A paired extension attributes foreground browser time to the selected normal tab and supplies duration-based web-media checkpoints.

It counts activity, not content.

Keyboard and mouse activity is stored as aggregate counts with capture timestamps. TimeLens does not record key values, typed text, messages, passwords, document contents, or screenshots.

Tray application

Runs quietly in the Windows notification area and owns the local tracking service.

Local dashboard

Served only from 127.0.0.1:47821 while TimeLens is running.

Browser companion

Adds domain, tab, audible-media, and web-blocking context.

Local database

Stores your activity under %LOCALAPPDATA%\TimeLens.

04

FOUNDATIONS

How TimeLens counts time

TimeLens keeps the foreground ledger and concurrent-media ledger separate. This prevents an app from receiving time while it is no longer in front, while still preserving music, podcasts, tutorials, and picture-in-picture playback that continue in the background.

Foreground app time

Exactly one eligible application owns each active moment. Alt-tabbing closes the previous segment and starts the next one.

Foreground web time

When the foreground app is a browser, the paired extension attributes that same interval to the selected normal tab. It is a breakdown, not extra time.

Concurrent media

Playing Spotify audio or web video is recorded separately and may overlap foreground work. It never increases the primary Active time total.

Idle and away

After the configured input threshold, foreground activity stops accumulating until activity resumes. Proven media progress can continue on its separate ledger.

ALT-TAB EXAMPLE

Use VS Code for 2 hours, watch YouTube in the foreground for 30 minutes, then code for 1 more hour. Apps shows VS Code 3h, the browser 30m, and primary Active time 3h 30m—not 3h 30m for VS Code.

BACKGROUND MEDIA EXAMPLE

Code for 2 hours while Spotify plays, or keep a tutorial in picture-in-picture while another app is foreground. The foreground app receives up to 2 hours of Active time; Spotify or the tutorial receives up to 2 hours of concurrent playback. These values describe overlapping facts and must not be added together as a workday total.

A day still has a hard boundary.

Primary active, app, category, timeline, and foreground-site summaries use the exclusive ledger and cannot legitimately exceed the elapsed local day. Concurrent playback is displayed separately because several real activities can happen during the same wall-clock minute.

DASHBOARD

Today

The Today tab is a live summary of the current date. Active time excludes idle and away periods. Input totals are counts—not typed content. The unchanged compact GitHub-style heatmap is anchored on the left; Day snapshot expands on its right to use the full available row. Category and app colors automatically follow the selected theme.

Active time
Exclusive foreground activity after idle time is removed.
Focus score
The rounded percentage of scored active time in Development, Work, Documents, Communication, and Design. “Other” is removed from the denominator; if all scored time is Other the neutral value is 50, and a day with no active time is 0.
Day snapshot
Shows current foreground state, most-used app, leading category, concurrent web-media duration, and browser-visit count without repeating the Focus score card.
Categories
The larger donut and ranked bars group time using built-in and custom Rules without changing the card footprint.
The focus score is category-based.

It does not inspect document content, judge the quality of work, or reward rapid app switching. Classification rules directly affect the score, so fix an incorrect category before interpreting it.

Arrange the dashboard.

Hover a movable card and drag its grip. TimeLens remembers card order separately for each page. Use Alt + an arrow key while the grip is focused for keyboard reordering.

DASHBOARD

History

History answers what happened on a specific day and how activity changes over time. Select a heatmap square, use the date field, or move through days with the arrow controls. The selected date is encoded in the URL, so refreshing or using browser Back and Forward preserves the page and date.

  • The compact activity heatmap offers 3-month, 6-month, and 1-year ranges without a horizontal page scrollbar.
  • The heatmap visualization and 960-pixel desktop width are unchanged in 8.1. It is aligned to the content edge instead of centered inside unused space.
  • At a glance fills the remaining right-hand width and matches the heatmap’s row height.
  • Month labels, weekday guides, theme-aware intensity levels, and hover details use the familiar contribution-calendar pattern.
  • Daily cards compare active time, focus, input, and idle time.
  • At a glance highlights the leading app, category, browser visits, activity segments, and session balance.
  • Lower cards contain the selected day’s apps, categories, browser data, and expandable timeline.
07

DASHBOARD

Apps

Apps provides an application-first view: time, keyboard counts, and mouse counts for each executable. Each row uses three clear columns: application, a centered theme-aware activity-share bar, and a right-aligned time value. Use the Uncategorized section to assign an app without leaving the page; TimeLens creates a categorization rule for future events.

Names come from Windows.

Entries such as ApplicationFrameHost.exe or helper processes may be normal Windows hosts. Categorize the executable you actually want grouped; avoid broad rules that could catch unrelated programs.

08

DASHBOARD

Browser and web media

Browser is distinct from Apps: it uses paired extension events for the selected date. Overview ranks domains and shows hourly foreground use; Visits lists each focused interval with start time, duration, browser, title, URL, and known input counts; Pages aggregates matching page records. A browser executable can have active time even when no domain event is available.

Active browsing
Time when a browser was the foreground Windows app and the extension identified its selected normal tab.
Media playback
Duration proven by media-element position changes or a lower-confidence audible-tab fallback. It may continue in a background tab or picture-in-picture.
Visits
Focused tab intervals. Many short visits do not imply equal time; duration is the useful measure.
Pages
Normalized page-level totals, subject to the selected page-title and URL privacy settings.
Why three hours of YouTube may not say three hours of Active browsing.

If YouTube played behind VS Code or in picture-in-picture, VS Code correctly owns foreground time and YouTube belongs under Media playback. In 7.9 the extension sends media position, duration, and playback-rate checkpoints; TimeLens accepts real progress, rejects forward seeks as watched time, and can reconcile a suspended gap for up to 30 minutes when the later media position proves continuous playback.

About the attribution warning

The percentage compares attributable site intervals only with foreground-browser time during periods when the extension was actually observed. It appears only for today after at least 30 minutes of browser use, at least 15 minutes are unexplained, and coverage is below 70%. Internal browser pages, private windows, a missing profile extension, sleep, or the interval before reconnection can still be unmatched. Granting permissions cannot backfill time that was never reported.

Media tracking is conservative by design.

Paused video, buffering, seeking, muted tabs without advancing media, browser shutdown, and restricted pages are not guessed as watched time. Update both the desktop app and extension before judging a new session; old gaps remain historical.

Stops desktop relaunches or shows the custom full-page website screen.

  2. 2
    Pick a mode and target

    Search running executables or paste a website URL.

  3. 3

Use Kill and Strict carefully.

Unsaved work in a terminated application can be lost. Never target Windows shells, security software, or TimeLens itself.

CONTROL

Password protection

Password protection is optional. Choose whether it applies to Strict targets only or every focus target, and whether the tray Exit command needs a password.

  • Open Settings → Block password and create a password of at least six characters.
  • With Strict targets only selected, removing or weakening a Strict app or website requires the password. Choose All focus targets to cover every entry.
  • The password is converted to a salted PBKDF2 hash and stored locally; the original password is not retained.
  • Unlock attempts are throttled to slow casual guessing. Changing the protection scope or disabling protected exit also asks for the password.
  • Protection prevents casual dashboard and tray bypasses. Windows Task Manager can still end a normal user process; separate Windows accounts and a locked screen are required for stronger PC security.
Keep the password somewhere safe.

TimeLens cannot reveal a forgotten password. Removing local settings can reset protection, but also changes your local configuration.

Rules & categories

Rules determine how apps and domains are labeled. Built-in rules provide sensible defaults; custom rules override or extend them.

Target
Choose executable for desktop apps or domain for websites.
Match type
Use the narrowest available match—exact before broader substring or pattern matching.
Category
Select an existing category or create a meaningful custom label.
Priority
When multiple custom rules match, their order determines which classification wins.

EXAMPLE

Target: executable · Pattern: Code.exe · Match: exact · Category: Development
Test broad rules.

A substring like code could classify several unrelated executables. Prefer an exact executable or domain whenever possible.

REFERENCE

Privacy & local data

TimeLens has no account system, remote profile, analytics SDK, advertising identifier, or cloud synchronization. The dashboard listens on the loopback address rather than the public network.

DATABASE%LOCALAPPDATA%\TimeLens\activity.db
  • Use Settings → Data & storage to control automatic retention.
  • CSV and JSON exports create portable copies; treat them as personal data.
  • Browser page-title storage can be disabled in Privacy center; timeline title visibility is a separate display setting.
  • The extension sends aggregate counts and media timing metadata, never typed characters, page contents, screenshots, audio, or video.
  • Back up the TimeLens folder before reinstalling Windows if you want to retain history.

Troubleshooting

The dashboard does not open

Confirm the tray icon is running, then open http://127.0.0.1:47821/. The address intentionally remains local to your PC. If another TimeLens instance exists, close all copies and launch the newest EXE once.

The extension and dashboard show different connection states

Install desktop version 8.1 and companion version 8.0, keep the tray app running, then press Connect once and wait for both surfaces to refresh. Different version numbers are expected for this release because the extension did not require code changes. A saved profile normally survives PC restart. Generate a new code only when the extension says Pair/Not connected, the credential was revoked, the extension was reinstalled, or this is a different browser profile.

YouTube or another web player shows much less time than I watched

First compare Media playback—not only Active browsing. Background and picture-in-picture video is concurrent media. Confirm the popup says Connected, the desktop and extension both show 7.9, and test with a newly played video; an update cannot reconstruct old missing sessions. Restricted browser pages and private windows need separate permission or remain intentionally excluded. Pauses, seeks, buffering, and non-advancing media are not counted.

I granted every permission but still see an attribution warning

Permissions allow future events; they do not repair time before the extension connected. The diagnostic uses only the period where the extension was observed and requires substantial missing time before warning. Confirm the extension is installed and paired in the exact profile you are using. Internal browser pages and intentionally excluded private windows may remain unattributed.

Refreshing returns me to another page

Version 8.1 keeps the active dashboard view and relevant selected date in the URL. If an older tab still resets, close it, open the dashboard from the 8.1 tray app, and refresh once.

Website blocking does not work

Website enforcement requires the extension. Confirm Focus Mode is enabled, the entry is a domain rather than a full URL, and the current browser has the TimeLens extension loaded.

An app is categorized incorrectly

Open Rules, look for a custom rule that is too broad, and replace it with an exact executable or domain match.

Cards are in the wrong order

Open Settings → Card layout, choose the affected page, and reset it. You can also reset all saved layouts.

Update or remove TimeLens

UPDATE

Update from Settings

Settings shows both your installed version and the available version. Choose Update now and TimeLens verifies the download, replaces the EXE, restarts, opens a fresh dashboard, and displays the centered release notes once. Your local database stays in place. If Windows blocks replacement, download and run the current Setup installer once. Update the browser companion separately when its store or release package changes.

REMOVE

Use Windows uninstall

Exit TimeLens, then remove it from Windows Settings → Apps → Installed apps. Delete %LOCALAPPDATA%\TimeLens separately only if you also want to permanently erase history and settings.
