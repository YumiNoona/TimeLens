Start here

Understand the whole app

Link to section ↗

This is the complete guide to the Windows EXE and its local dashboard, with a separate Android reference. Start with setup, then use the control tables, examples and diagnostics to configure TimeLens for your own workflow.

Windows tray app

The native EXE observes foreground apps, idle/away state and optional input/audio signals. It writes a local SQLite database and serves the dashboard while running.

Local dashboard

Open http://127.0.0.1:47821/ to inspect activity, configure rules, enforce focus boundaries and export records. Closing the browser tab does not stop the EXE.

Browser companion 9.0.0

Pair a Chrome, Edge, Brave or Firefox profile to add website context and website blocking. Without it, Windows can still count the browser executable.

Native Android app

Today, Apps, History, Block and Settings use Android permissions and keep a separate local archive. Windows and Android do not currently connect or sync.

A useful first session

  1. Install the Windows app and verify the tray icon.
  2. Choose your privacy settings before collecting a day of activity.
  3. Pair each browser profile you use.
  4. Check Today and Browser, then create one narrow categorization rule.
  5. Try a short, reversible focus target before configuring Strict blocks.
  6. Choose retention and make a backup plan.

Windows and Android display 1.0.0; browser companions display 9.0.0. This page describes the current release rather than the old 8.x documentation.

Start here

Tray behavior and daily operation

Link to section ↗

The tray icon is the control point for the running EXE. If Windows hides it, open the notification-area overflow beside the clock. Use Open Dashboard to reopen the local interface, and use Exit when you intend to stop collection.

Setup vs portable
Setup adds the normal Windows installation/uninstall flow and optional shortcuts. The portable EXE includes the embedded runtime and dashboard; it still stores activity under your Windows user profile, not beside the EXE.
Launch at login
Enable it in Settings → General or during Setup. Sign-in starts the tray app; opening the dashboard remains a separate action. For an advanced startup shortcut, TimeLens.exe --startup uses the quiet startup path.
Closing a dashboard tab
Collection continues while the tray app is running. Browser pairing also needs the local app to remain running.
Multiple EXEs
The normal application uses a single-instance guard. Starting another copy is not a way to create a second database or another independent tracker.
Exit protection
If configured, an active protected focus target can require the block password before tray Exit. An empty list or expired timers do not hold the app open.

Track only the signed-in account and session you intend to use. Do not expose the local dashboard through a public port, reverse proxy or port-forwarding rule.

Install and pair every browser profile

Link to section ↗

The Windows app works without a companion, but cannot infer individual websites from an executable name. Companion 9.0.0 adds selected-tab observations, aggregate website input, supported media checkpoints and configured website enforcement.

Chrome, Edge and Brave

  1. Download the matching ZIP from Downloads and extract it to a stable folder.
  2. Open chrome://extensions, edge://extensions or brave://extensions.
  3. For local package installation, enable Developer mode and choose Load unpacked. Select the extracted folder containing manifest.json, not the ZIP.
  4. Keep the folder in place. After replacing its files with an update, reload the extension from that browser's Extensions page.

Firefox

Use a Mozilla-signed add-on for normal release Firefox installation. The Firefox listing may remain on an earlier version until the maintainer publishes 9.0.0. The GitHub ZIP is the submission/source package, not an already signed XPI. Temporary developer installation is not a persistent normal-user installation.

Pair the profile

  1. 1
    Start TimeLens

    Open its local dashboard and Settings → Privacy center.

  2. 2
    Generate a code

    Choose Connect. The eight-digit code lasts two minutes and is copied when clipboard access is available.

  3. 3
    Enter it in the extension

    Open the popup in the browser profile you actually browse with, paste the code and choose Pair.

  4. 4
    Confirm both sides

    Wait for Connected, open a normal HTTPS site and check new activity in Browser.

Not paired / Pair
No accepted local credential exists for this profile. Generate a new code.
Connecting / Checking
The extension is checking the local app or exchanging the short-lived code.
Connected
The app recently observed the companion. Check the separate collection switches if activity is still disabled.
Desktop offline / paired offline
The profile still has a token but cannot currently reach the EXE. Start the app before replacing a valid pairing.
Rejected / outdated
Re-pair a rejected credential, or update an incompatible companion. A stored token alone is not evidence of a working connection.

Pair each profile separately, including profiles in different browsers. Up to 16 saved profile credentials are retained; pairing another profile does not normally disconnect the others. The Disconnect/revoke control invalidates the saved extension access collectively, so pair the profiles you still want again afterwards.

Private browsing is excluded.

The companion skips incognito/private tabs even if browser permission is granted. Internal pages such as browser settings, extension pages and other restricted URLs do not produce normal website observations. Android address-bar tracking has a different boundary; see its own chapter.

Collection is event-driven, with a bounded recovery alarm approximately every 30 seconds. A temporarily offline extension does not replay an old focused tab as if it were still current. Aggregate input retries use stable IDs; a closed or unsupported page cannot be reconstructed as complete browsing history.

05

Understand the data

How time is counted

Link to section ↗

Foreground time and concurrent media answer different questions. Adding them together as one exclusive total would double-count time.

Foreground app
One executable owns a Windows foreground interval. Fast switches retain their recorded seconds rather than becoming several rounded-up minutes.
Idle
The new-install threshold is 180 seconds since input. Qualifying playback in the foreground app/browser can sustain active state, bounded to two hours without input. Background music does not turn an unattended editor into active work.
Away
Lock and sleep are distinct from active use. Gaps or interrupted observations are not guessed as continuous work.
Website time
A subset of browser foreground time attributed to an observed normal tab. It is not additional app time.
Media time
A separate concurrent signal for supported playback, including background and picture-in-picture. Media position/rate checkpoints avoid treating seeks or buffering as watched duration.
Input counts
Aggregate keystroke and pointer counts at their capture times. Key values, typed text, messages and passwords are not recorded.
Dates and recovery
Daily reports use local date boundaries. Durable checkpoints, not the next launch time, close unfinished records after interruption. Time-zone changes and daylight-saving boundaries can affect which local day a timestamp appears on.

WORKED EXAMPLE

You spend 30 minutes in the browser, then 30 minutes coding while a web video keeps playing. The exclusive app total is one hour: browser 30 minutes + editor 30 minutes. Website foreground time belongs within the browser's 30 minutes. Proven background video playback belongs to the separate media ledger.

A real gap is still a gap. Missing permissions, a disconnected profile, an excluded site, a stopped EXE, private browsing or suspended Windows cannot be repaired simply by enabling every setting later.

Dashboard pages

Today and the focus score

Link to section ↗

The Today tab is a live summary of the current date. Active time excludes idle and away periods. Input totals are counts—not typed content. The compact Windows heatmap is anchored on the left; Day snapshot expands on its right to use the full available row. Category and app colors automatically follow the selected theme.

Active time
Exclusive foreground activity after idle time is removed.
Focus score
The rounded productive share of scored active time. Productive categories are Development, Work, Documents, Communication and Design. “Other” is removed from the denominator; if all active time is Other the neutral value is 50, and a day with no active time is 0.
Day snapshot
Shows current foreground state, most-used app, leading category, concurrent web-media duration, and browser-visit count without repeating the Focus score card.
Categories
The category donut and ranked bars group time using built-in and custom Rules without changing the card footprint.
The focus score is category-based.

It does not inspect document content, judge the quality of work, or reward rapid app switching. Classification rules directly affect the score, so fix an incorrect category before interpreting it.

Arrange the dashboard.

Hover a movable card and drag its grip. TimeLens remembers card order separately for each page. Use Alt + an arrow key while the grip is focused for keyboard reordering.

History and date navigation

Link to section ↗

History answers what happened on a specific day and how activity changes over time. Select a heatmap square, use the date field, or move through days with the arrow controls. The selected date is encoded in the URL, so refreshing or using browser Back and Forward preserves the page and date.

  • The compact activity heatmap offers 3-month, 6-month, and 1-year ranges without a horizontal page scrollbar.
  • The Windows heatmap is compact and aligned with the report content. Android uses a different History layout without the long calendar grid.
  • At a glance fills the remaining right-hand width and matches the heatmap’s row height.
  • Month labels, weekday guides, theme-aware intensity levels, and hover details use the familiar contribution-calendar pattern.
  • Daily cards compare active time, focus, input, and idle time.
  • At a glance highlights the leading app, category, browser visits, activity segments, and session balance.
  • Lower cards contain the selected day’s apps, categories, browser data, and expandable timeline.
08

Dashboard pages

Apps, input and uncategorized activity

Link to section ↗

Apps provides an application-first view: time, keyboard counts, and mouse counts for each executable. Each row uses three clear columns: application, a centered theme-aware activity-share bar, and a right-aligned time value. Use the Uncategorized section to assign an app without leaving the page; TimeLens creates a categorization rule and can backfill matching unclassified records. It does not indiscriminately recategorize every previously classified event.

Names come from Windows.

Entries such as ApplicationFrameHost.exe or helper processes may be normal Windows hosts. Categorize the executable you actually want grouped; avoid broad rules that could catch unrelated programs.

09

Dashboard pages

Browser reports and web media

Link to section ↗

Browser is distinct from Apps: it uses paired extension events for the selected date. Overview ranks domains and shows hourly foreground use; Visits lists each focused interval with start time, duration, browser, title, URL, and known input counts; Pages aggregates matching page records. A browser executable can have active time even when no domain event is available.

Active browsing
Time when a browser was the foreground Windows app and the extension identified its selected normal tab.
Media playback
Duration proven by media-element position changes or a lower-confidence audible-tab fallback. It may continue in a background tab or picture-in-picture.
Visits
Focused tab intervals. Many short visits do not imply equal time; duration is the useful measure.
Pages
Normalized page-level totals, subject to the selected page-title and URL privacy settings.
Why three hours of YouTube may not say three hours of Active browsing.

If YouTube played behind VS Code or in picture-in-picture, VS Code correctly owns foreground time and YouTube belongs under Media playback. Foreground website attribution uses the exact same exclusive, idle-free Windows timeline as Apps and Timeline, so an old browser row cannot continue through time owned by another app. Media checkpoints use position and playback rate to keep proven playback while omitting buffering and seeks, including the final interval reported by a pause.

About the attribution warning

The percentage compares attributable site intervals only with foreground-browser time during periods when the extension was actually observed. It appears only for today after at least 30 minutes of browser use, at least 15 minutes are unexplained, and coverage is below 70%. Internal browser pages, private windows, a missing profile extension, sleep, or the interval before reconnection can still be unmatched. Granting permissions cannot backfill time that was never reported.

Media tracking is conservative by design.

Paused video, buffering, seeking, muted tabs without advancing media, browser shutdown, and restricted pages are not guessed as watched time. Update both the desktop app and extension before judging a new session; old gaps remain historical.

Focus and classification

Configure app and website blocks

Link to section ↗

Add an executable name such as discord.exe or a domain such as youtube.com, choose how long it should remain blocked, and enable Focus Mode to enforce the list.

01Notify

Shows the saved reminder in your selected screen corner while the website remains usable.

02Hide

Minimizes a matching desktop application window.

03Kill

Terminates a matching desktop process immediately.

04Strict

Stops desktop relaunches or shows the custom full-page website screen.

  1. 1
    Choose App or Website

    Apps offer Hide, Kill, and Strict; websites offer Notify and Strict.

  2. 2
    Pick a mode and target

    Search running executables or paste a website URL.

  3. 3
    Set the duration

    Choose 15/30 minutes, 1/2/4 hours, a custom duration in minutes/hours/days (up to one year), or No limit. No limit means until you remove the target, not a daily quota.

  4. 4
    Enable protection

    Choose Strict targets only or all focus targets, then require a password before protected entries can be removed.

Use Kill and Strict carefully.

Unsaved work in a terminated application can be lost. Never target Windows shells, security software, or TimeLens itself.

Check your first rule

  1. Add one harmless target for 15 minutes.
  2. Enable Focus Mode; storing a target alone does not turn enforcement on.
  3. For apps, use the entry's Test now action when available, then try opening the app normally.
  4. For a website, test in the exact paired profile on a fresh normal tab.
  5. Check the attempt count/last attempt, then remove the test rule.

Domain targets include matching subdomains. A pasted website address is normalized to a domain; this is not a general URL-path blocker. A Strict website target redirects through the extension's block page. If the extension or EXE is stopped, its normal enforcement path is unavailable.

Windows timers are not Android allowances.

A Windows duration keeps a target blocked until its expiry. Android Comfort instead grants usage minutes in a rolling 24-hour window. Do not interpret a Windows 1-hour block as permission to use an app for one hour each day.

Title / message
Title: up to 60 characters. Message: up to 240 characters. {target} inserts the app/domain and {mode} inserts the enforcement mode.
Images
PNG, JPEG and GIF, up to 4 MB. Use a small asset if you want a lightweight reminder.

A Notify website rule leaves the page usable and repeats the reminder. Strict uses a blocking page. Desktop modes use the native reminder/presentation alongside their enforcement action; changing the artwork does not change the action itself. Uploaded media stays in local app storage.

Focus and classification

Password scope and protected exit

Link to section ↗

Password protection is optional. Choose whether it applies to Strict targets only or every focus target, and whether the tray Exit command needs a password.

  • Open Settings → Block password and create a password of 6–128 characters.
  • With Strict targets only selected, removing or weakening a Strict app or website requires the password. Choose All focus targets to cover every entry.
  • The password is converted to a salted PBKDF2 hash and stored locally; the original password is not retained.
  • Unlock attempts are throttled to slow casual guessing. Changing the protection scope or disabling protected exit also asks for the password.
  • Protection prevents casual dashboard and tray bypasses. Windows Task Manager can still end a normal user process; separate Windows accounts and a locked screen are required for stronger PC security.
Keep the password somewhere safe.

TimeLens cannot reveal a forgotten password. Removing local settings can reset protection, but also changes your local configuration.

Focus and classification

Rules, matching and priority

Link to section ↗

Open Rules to classify activity. The current match choices are Contains, Glob (*) and Regex; targets are Exe name, Window title or Domain. There is no separate Exact selector in this screen.

Contains
Case-insensitive substring matching. Convenient, but a pattern such as code may also match unrelated executable names.
Glob (*)
The whole target must match. * matches any sequence and ? one character. To match only Code.exe, use Glob with Code.exe and no wildcards.
Regex
Case-insensitive regular expression, with a bounded execution timeout. Anchor it for a narrow match, for example ^code\.exe$. Invalid/overly expensive patterns do not provide a useful matching rule.
Priority
Custom rules are checked in ascending priority; the first matching custom rule wins. Drag the list to put a narrower exception ahead of a broad rule.
Built-ins
Built-in executable/domain mappings provide fallbacks. Custom rules can override them for new classification, subject to special handling of Windows system hosts.
History
Adding/updating a rule also attempts to classify matching records that are still Other/unclassified. It does not rewrite every already classified record. Removing a rule does not mean all previous categories are automatically undone.

Examples you can adapt

TargetMatchPatternCategory / intent
Exe nameGlob (*)Code.exeDevelopment, only that executable
Exe nameGlob (*)idea*.exeDevelopment, matching IDE executables
DomainRegex(^|\.)example\.com$Work, the domain and its subdomains
Window titleContainsClient ProjectA project/category exception; put it ahead of broad app rules

Create a custom category when it helps your reports, but do not assume its name changes the Windows focus-score formula. A category called Productive is not automatically one of the five productive categories described in Today. Privacy rules can remove title/project context, so title-based classification may stop matching after you intentionally hide that data.

Configure Windows

Offline work and manual review

Link to section ↗

Enable Settings → Tracking → Offline work to show the optional panels in Today/History. They describe work away from keyboard input; they do not convert automatic idle spans into secretly active app time.

  1. Review an offered away/idle span, or choose Add untracked time and enter its start/end.
  2. Choose Meeting, Call, Brainstorming, Other offline work, Break or Personal.
  3. Optionally add a project and notes, then confirm/save.
  4. Remove an incorrect manual entry rather than trying to cover it with a second contradictory entry.

Offline work is reported separately from automatic active time and media. Break and Personal are not work. Disabling the feature hides its panels while preserving existing entries. Do not add offline time and automatic totals together without checking their time ranges.

Link to section ↗
Data & storage controls

Export a report

  1. Open Settings → Data & storage.
  2. Choose the period. For Custom dates, the end date must not be before the start date; both dates are inclusive.
  3. Choose CSV for analysis or JSON for structured records, then Export.
  4. Verify the saved file and its selected period before using it as an archive.

An export is a report, not a complete installation backup. Do not assume it includes every pairing credential, password setting, category rule, reminder asset or browser-local card arrangement. The Windows dashboard does not expose a general full-backup JSON restore wizard.

Back up the Windows installation data

  1. Exit TimeLens from the tray, satisfying configured password protection if required.
  2. Copy the complete %LOCALAPPDATA%\TimeLens directory to a protected backup location.
  3. Keep the database, any SQLite companion files present, configuration and reminder media together. Do not copy only a live activity.db while the EXE is writing to its WAL.
  4. To restore, stop TimeLens, preserve the destination's current data separately, restore the complete known-good folder, then start the same or a compatible build.

Browser-local layouts and extension-local pairing state are separate. Restoring only the Windows data folder can leave a browser needing to pair again. Treat backups as sensitive: URLs, titles, projects, notes and local credentials may be included. Never post the folder publicly for troubleshooting.

Delete activity vs uninstall

Privacy center's Delete activity erases collected activity while keeping settings/rules. Uninstalling the program and deliberately deleting its data directory are different operations. Back up before a destructive cleanup; collection exclusions are not a substitute for historical deletion.

Power-user reference

Practical configurations to start from

Link to section ↗

Minimal browsing detail

  1. Stored browser address → Domain only.
  2. Store page titles → Off.
  3. Window titles → Off.
  4. Add exact sensitive apps and website exclusions.
  5. Keep browser tracking only if domain totals are useful; choose an appropriate retention period.

Less title/path context is available for later diagnosis and title-based categorization.

Development/work review

  1. Pair your actual research-browser profiles.
  2. Use a Glob rule for Code.exe → Development.
  3. Place narrow project-title exceptions before broad app rules if retaining titles is acceptable.
  4. Use grouped Timeline for a daily summary; switch to Flat for individual events.
  5. Enable Show seconds when investigating short switches.

Category scores are a lens on recorded activity, not an assessment of work quality.

Fewer live UI updates

  1. Dashboard refresh → 60 or 120 seconds.
  2. Smooth motion → Off if desired.
  3. Use a plain text/image reminder rather than looping video.
  4. Close unused dashboard tabs.
  5. Keep only the collection signals you want.

Closing a dashboard tab keeps the tracker running. Changing UI polling is not a new capture-rate setting.

A reversible focus session

  1. Add a 30-minute website Notify target.
  2. Use a calm message and a five-minute repeat interval.
  3. Verify the paired profile receives it.
  4. Change to Strict only after testing the target.
  5. Choose password scope deliberately if you want friction against removing the target.

Do not test Kill/Strict on an application with unsaved work.

Inspect and configure the local API

Link to section ↗

The dashboard uses a loopback HTTP API owned by the running EXE. It is an internal interface rather than a promised permanent external API. The normal UI is the supported path for protected changes. Examples below must run from the local TimeLens dashboard's developer console, not this public documentation website.

Read current settings

await fetch('/api/settings').then(async response => {
  if (!response.ok) throw new Error('Open the local dashboard and try again');
  console.table(await response.json());
});

A small, reversible display change

This example deliberately enables seconds and makes the dashboard poll once a minute. It does not change collection frequency or weaken protection.

await fetch('/api/settings', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ showSeconds: true, pollIntervalSeconds: 60 })
}).then(async response => {
  if (!response.ok) throw new Error(await response.text());
});
// Reload the dashboard so every visible control reads the saved values.

To return to the new-install display defaults, use { showSeconds: false, pollIntervalSeconds: 30 } with the same request. Inspect the HTTP response; invalid keys or out-of-range values can be rejected. Back up first if you are exploring more than simple display settings.

Useful read-only endpoints

GET /api/settings
Current app settings, including privacy/display choices. Do not publish the response without reviewing it for sensitive exclusions or paths.
GET /api/summary?date=YYYY-MM-DD
The selected local day's dashboard report.
GET /api/extension-status
Pairing, recent connection, companion version and coverage diagnostics.
GET /api/rules
Saved custom classification rules and their order.
GET /api/db-size
Local storage usage reported by the EXE.

Dashboard sessions use a local HttpOnly, SameSite cookie; extension pairing uses a separate restricted credential. Do not copy tokens into third-party tools, embed them in scripts you share, or disable origin/loopback protections to make a request work. Reopen the dashboard after a restart if a stale session is rejected.

Reset only this browser's card layouts

This removes saved card order for this dashboard origin, then reloads it. It does not delete SQLite activity, app settings, all browser storage, or extension pairing. Use it only when you actually want to restore the default arrangement.

Object.keys(localStorage)
  .filter(key => key.startsWith('timelens.card-layout.v1.'))
  .forEach(key => localStorage.removeItem(key));
location.reload();

Compatibility fields are not all current controls

For example, timelineMinSegmentSeconds is retained as a validated compatibility setting (30/60/120/300) but is not exposed as a current quick-switch selector; the current Timeline preserves short normalized visits. Windows also has internal goal-record endpoints, but the current dashboard does not ship a complete goal-manager/reminder workflow. Android daily goals are a separate implemented feature. Do not interpret an internal field or route as a fully supported UI feature.

When reporting a problem

  • Include the Windows/Android version and browser companion version separately.
  • State the affected page, local date, browser/profile and exact steps.
  • For tracking, distinguish app time, website foreground time and media time.
  • For blocking, include target type, action, duration, Focus Mode state and extension/service connection.
  • Review logs, screenshots and exported records before sharing; redact titles, domains, projects, notes and credentials.

A plain idle tracker uses fewer resources than multiple open dashboards, large histories being queried, looping reminder media or active playback. Measure the workload you actually use instead of treating a single idle benchmark as an all-day guarantee. The app requires its local loopback port; running as administrator or opening a firewall port is not the normal setup fix.

Android setup and permissions

Link to section ↗

Download the signed Android APK for Android 10 or later. The AAB in the release is for Play Console upload, rather than direct installation.

  1. 1
    Allow Usage access

    This reads foreground app usage and measures app allowances. TimeLens does not request Internet access.

  2. 2
    Explore your activity

    Check Today, search and filter Apps, or open History for range totals and per-app visits. Each app has one total with an expandable visit list.

    Set up optional blocking

    Open Block, read the disclosure and enable the Android Accessibility service. A downloaded APK may require Allow restricted settings in Android App info first.

  4. 4
    Make it yours

    Use the top sun/moon for light or dark mode. Settings controls dashboard modules, icon colors, compact cards, clocks, retention and privacy.

The APK is directly installable; the AAB is for Play Console upload. Current signed Android releases retain an increasing internal build code, allowing the displayed reset to 1.0.0 to update signed 5.0.0 in place. An older preview with a different certificate cannot be updated by this signing key.

Maintenance

Troubleshoot the right layer

Link to section ↗
The dashboard does not open

Confirm the tray icon is running, then open http://127.0.0.1:47821/. The address intentionally remains local to your PC. If another TimeLens instance exists, close all copies and launch the newest EXE once.

The extension and dashboard show different connection states

Use Windows 1.0.0 with companion 9.0.0, keep the EXE running and inspect the exact profile. Connected means recent contact, not just a stored credential. Start the EXE before replacing a valid pairing. Re-pair only when credentials are missing/rejected/revoked or you changed profiles. A store listing can still be on an earlier version until its maintainer publishes the new package.

YouTube or another web player shows much less time than I watched

First compare Media playback—not only Active browsing. Background and picture-in-picture video is concurrent media, while Active browsing requires the browser to own the Windows foreground. Confirm the popup says Connected and test a newly played video after updating Windows to 1.0.0 and the companion to 9.0.0. Restricted pages and companion private/incognito tabs remain excluded. Pauses, seeks, buffering, and non-advancing media are deliberately not counted, and an update cannot reconstruct events that were never reported.

I granted every permission but still see an attribution warning

Permissions allow future events; they do not repair time before the extension connected. The diagnostic uses only the period where the extension was observed and requires substantial missing time before warning. Confirm the extension is installed and paired in the exact profile you are using. Internal browser pages and intentionally excluded private windows may remain unattributed.

Refreshing returns me to another page

The dashboard keeps the active dashboard view and relevant selected date in the URL. If an older tab still resets, close it, open the dashboard from the current tray app, and refresh once.

Website blocking does not work

Website enforcement requires the extension. Confirm Focus Mode is enabled, the entry is a domain rather than a full URL, and the current browser has the TimeLens extension loaded.

An app is categorized incorrectly

Open Rules, look for a custom rule that is too broad, and replace it with an exact executable or domain match.

Cards are in the wrong order

Use the card grips or Alt + arrow keys to rearrange them. Layouts belong to this dashboard browser. The advanced chapter explains how to reset only the layout keys without clearing database activity or all browser site data.

A categorization rule does not match

Confirm Exe name vs Window title vs Domain, then Contains vs Glob vs Regex. Use Glob without wildcards for a whole-name match. Move a narrow rule above broad rules. Title hiding or redaction can intentionally remove matching context. Existing classified history is not all rewritten when a rule changes.

A lower refresh rate seems to miss short switches

Dashboard polling controls screen refresh, not capture granularity. Turn on Show seconds and inspect Flat Timeline before judging a rounded display. Also check idle, pause and collection exclusions.

Android does not show websites or enforce a rule

Check Usage access, master blocking, the Accessibility service and separate website-tracking opt-in. Review battery restrictions and try a supported visible address bar. A hidden bar or unsupported browser version can leave gaps; it is not repaired by granting unrelated permissions.

I cannot find a setting described elsewhere

This guide distinguishes Windows from Android and labels internal/compatibility fields. The current Windows Rules UI has Contains/Glob/Regex, not an Exact selector; Android Comfort is not a Windows timer; a raw API field does not necessarily have a dashboard control.

Updates, version reset and removal

Link to section ↗

UPDATE

Update from Settings

Settings shows both your installed version and the available version. Choose Update now and TimeLens verifies the download, replaces the EXE, restarts, opens a fresh dashboard, and displays the centered release notes once. Your local database stays in place. If Windows blocks replacement, download and run the current Setup installer once. Update the browser companion separately when its store or release package changes.

REMOVE

Use Windows uninstall

Exit TimeLens, then remove it from Windows Settings → Apps → Installed apps. Delete %LOCALAPPDATA%\TimeLens separately only if you also want to permanently erase history and settings.

Installing the reset release

Older higher-numbered Windows builds do not automatically downgrade to 1.0.0. Install the current Setup or deliberately replace the portable EXE after exiting the old copy. Keep the existing data directory and make a backup first. Future updates follow the new version line. Update browser companions separately; GitHub ZIP publication is not a browser-store auto-update.

Windows/Android app version 1.0.0 and companion version 9.0.0 are intentionally different. Native Android updates additionally depend on the signing identity and internal build code, not only the displayed number.
